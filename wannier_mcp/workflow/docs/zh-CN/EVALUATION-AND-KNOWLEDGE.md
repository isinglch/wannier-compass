# 独立测试与经验积累

## 1. 区分三个运行模式

| 模式 | AI可读的数据 | 用途 |
|---|---|---|
| 开发回放 | 开发材料及历史结果，来源显式记录 | 排查工具、校准通用规则，不作为独立泛化证明 |
| 独立盲测 | 固定发布包、允许的结构与计算设置、当前DFT投影、本轮产生的试算结果 | 测试规则和AI能否独立做出有效模型；经验检索关闭 |
| 经验辅助 | 当前数据加允许检索的既有案例 | 测试检索是否减少失败轮数、时间和计算成本；单独报告 |

元素、结构、SOC、DFT能带及投影属于合法输入，不必隐藏。应隔离的是历史最终投影基组、窗口、手调记录、成功模型、验收图、golden文件及能导向这些内容的文档、工具返回值和日志。不能把已有成功输入中的Wannier设置混入初始INCAR或其他模板。

评测准备方也应检查输入元数据。缓存中的自由文本名称、原目录、能量来源路径可能携带历史信息；对被测AI只保留必要数值和中性案例ID，原始来源映射由评测方私有保存。原始OUTCAR也可能回显Wannier设置，不能因其名为DFT输出就自动认为无答案。盲测运行器拒绝`historical_control`作为主体组来源；检验这一点属于执行层责任。

已经用于修改规则的材料归入开发集；让新AI重做这些材料可以检查实现与复现，但仍不是未见材料的独立测试。规则冻结后再使用保留材料或材料族评估泛化。相同结构的换目录、重复计算、近重复构型不能被当作互不相关的新案例。

## 2. 盲测交付与运行边界

私有开发工作区可能含案例资料，而本分发仓库只含白名单工具和文档。不能把整个历史工作区或研发对话交给被测 AI；发布清单记录每个通用文件的哈希。发布包不是访问控制器：把它放在一个新目录，不会阻止拥有全盘/SSH权限的 AI 读到别处的历史结果。

实际评测需要全新上下文，以及只暴露本轮工作区、白名单输入和所需执行工具的环境。用文件权限、独立账号/容器或工具端限定读写范围来实现；仅靠提示“不要看”不足以建立隔离。执行器不得把历史目录搜索、旧日志、经验检索或结果缓存作为隐式回退。盲测不提供经验库凭证或检索入口。

每轮开始固定：案例ID、模型目标、允许输入及哈希、发布包哈希、模型/提示版本、预算、验收范围、经验访问模式。运行中允许AI看自己这轮生成的失败与成功结果来迭代。由评测方独立保存历史参考，封存提交结果和工具访问日志后再比对；参考结果不传回正在接受同一轮评测的AI。

本地程序可以检查记录和打包内容，不能证明外部运行器真的隔离了上下文、文件系统或知识访问。服务器执行层部署时需单独验证这些边界。

## 3. 经验库的建议结构

这里规定后续设计，不宣称向量库已建成。采用一个可查询案例库，而不是要求AI逐个翻项目文件夹：

1. **结构化案例记录**保存可比较的事实：结构标识/去重信息、化学与结构特征、模型目标、XC/赝势标识/SOC与磁性、能量参考、k采样、NBANDS、基组、窗口、规则与工具版本。
2. **试算轨迹和证据存储**保存每轮决定、为何改窗/加轨道、失败原因、图、数值、计算开销与验收状态。成功与失败都入库；大文件用不可变内容哈希引用，不塞进文本向量。
3. **向量索引**索引有证据支持的经验摘要，用于找到相似问题；它不取代原始记录，也不把相似分数当成物理可靠性分数。

检索先检查目标范围和物理设置的可比性、评测集合排除条件，再结合结构特征和语义相似度排序。返回经验时同时给出适用条件、差异、来源、失败边界和验收证据。化学式相似本身不足以直接搬用轨道、能量窗口；历史能量值必须保留各自能量参考，作为当前投影复核的起点。

盲测材料及其近重复/同族保留组必须从可用检索集合排除。该过滤放在检索工具端，不能依靠LLM自觉忽略答案。经验辅助评测记录所用快照、过滤条件、查询和命中文档。盲测轮结束前保持结果隔离，评测结束后再决定入库；不能边测边把保留集答案加入后续同轮评测可读索引。

## 4. 怎么判断经验积累有用

分别报告无经验与经验辅助两种模式的成功率、预登记精度区/完整目标范围误差、缺失分支、所需试算轮数和成本。是否用到了同材料历史结果需明确说明。允许更快地复现已知材料，但这种能力与未见材料的泛化分开计分。

一份经验记录应区分“数值计数通过”“能带拟合通过”“目标物理量检查通过”“人工审阅”，保留未检查项。不能仅因图看起来相似、文件存在或有人标过成功，就将全部可靠性字段置为通过。


## 通用经验与材料答案的边界

“上方分界不安全时审阅更深的完整非目标谱块，只排除安全前缀；保留背景交给解纠缠，outer覆盖目标底部、frozen避开背景顶部”属于可迁移的物理经验，应进入通用skill。某材料对应哪些带号、哪些窗口、哪套基组拟合成功，则属于案例答案，不进入盲测发布包。允许读取当前材料的元素、结构和DFT数值；这与读取历史答案不同。

干净导出包不是整个开发仓库的脱敏副本，也不是操作系统权限隔离。历史案例、诊断和经验检索库须留在被测执行环境之外，盲测关闭经验检索。对已经参与规则开发的材料，即便新上下文未读取其答案，也应标为开发集无答案回放，不能据此宣称未见材料泛化；后者需要保留材料或结构族的独立测试集。当前知识向量库是规划，不是本包已实现功能。

## 当前可用的记录接口

[方案阶段与经验接口](DECISION-STAGES.md)已实现initial与real_first_try分开封存、后续试次追踪、技术重跑目录、结果快照和轨迹导出。initial只使用当前DFT与通用规则；AI审阅及经验输入单独记录。检索默认关闭，接口尚无真实backend；不会自动入库或宣称学习收益。消融可显式选择未改动的initial作为baseline臂，AI无经验臂另立case；真实检索臂待backend接入后再测。
