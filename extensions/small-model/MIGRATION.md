# 独立迁移说明

新项目与旧 `wannier-compass` 为并行目录。安装和运行不要求旧项目存在。旧 Cu 目录只作为可选的外部数据集；新项目没有对其绝对路径的运行时依赖。`examples/replay_cu.py` 的路径全部从命令行给出。

## 替换了哪些责任

| 旧责任/行为 | 新位置与行为 |
| --- | --- |
| 起草、conduction/independent review、assess、retry 等门职责 | planner、reviewer、evaluator、strategist 四个明确角色 |
| seal/启发式窗口构造 | 删除；planner 必须写明全部窗口边界 |
| 数值诊断转成科学否决或自动补数 | 删除；保留诊断，由角色决策 |
| 固定投影下限、化学先验强制证据、尾态门 | 不参与新校验；科学指导作为模型可见文本 |
| DFT/投影、方案窗口、同 k 点拟合绘图 | 已迁为独立展示能力，默认接入工作流；保留数值来源与路径约束，不调用旧策略引擎 |
| 闭合重试方向 | strategist 自由给出策略，planner 写出完整新方案 |
| 某份方案曾经通过即可继续执行 | 只能执行准确当前版本及其 reviewer 批准；每次修改重新批准 |
| 旧工作目录会话/经验的潜在复用 | 每次 workflow 新建会话；无恢复入口和旧记忆注入 |
| 总线堆叠多个科学裁决组件 | workflow 只路由，执行器只实现，角色输出科学判断 |

## 保留的基础能力

传输、每角色历史和独立模型压缩以原有基础实现为起点，已解除旧项目 import 并接入新角色、审计和运行目录。轨道列定义与 VASP 缓存转换器保留格式解析能力。它们不调用旧 bundle 的科学决策器、提示词摘要、seal 或化学数据库。

执行器、方案仓库、Schema、四角色交接和数据工具在新项目内实现。科学知识采用 MCP 项目原文快照：两份项目 skill 与 26 篇英文指导均随包保存，加载器按角色与阶段交付相关内容。旧工具命令和程序协议由适配说明明确区分，不恢复旧科学门控。首版手写科学摘要已退休，不再充当模型知识来源。原生适配器的 Cu 文件回放和打包验证见 `verification/`。不能把历史回放当作本版本经过了新的在线模型/DFT 全流程。

## 初次运行

1. 激活 Python 环境，安装本项目；或用本项目 src 运行。
2. 准备 SCF/band 数据，使用本项目 cache 转换器生成证据文件。
3. 修改 `configs/` 中合适的模型配置和软件命令，确认配置声明的实际服务容量。
4. 执行 `pythonagent run`；需要计算时使用 `--execute` 或设置 `execute=true`。
5. 查看本次新运行目录的 final-report、plans、handoffs、trials 和 calls。

新项目不实现旧目录的数据或契约同步。现有案例不被迁移脚本覆盖。
