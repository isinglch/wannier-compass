# WannierCompass scientific workflow

Begin with the [construction overview](docs/CONSTRUCTION-OVERVIEW.md): understand the required manifold, valence/conduction tradeoffs, expected fit and spread behavior, and failure diagnosis before applying individual metrics. Carry that physical picture into the [first-trial decision card](docs/FIRST-TRIAL-CARD.md). The [Chinese overview](docs/zh-CN/CONSTRUCTION-OVERVIEW.md) is for human reading; English is canonical for execution.

For compact tool operation and exact inputs/outputs, use [RUNTIME](docs/RUNTIME.md) and [INTERFACES](docs/INTERFACES.md). Evidence/selection do not require SSH or a scheduler. The [Slurm example](docs/SLURM-EXAMPLE.md) is an optional execution adapter; its cluster setup is not a universal requirement.


After the overview, use the short, executable [first-trial decision card](docs/FIRST-TRIAL-CARD.md) before choosing any orbitals or windows. The English card is operational; the [Chinese translation](docs/zh-CN/FIRST-TRIAL-CARD.md) is for human review. Use [detailed decision reasoning](docs/WORKFLOW-DECISIONS.md) when a branch is ambiguous, [physical reasoning](docs/PHYSICAL-REASONING.md) for interpretation, and [the selection interface](docs/MANIFOLD-SELECTION.md) for command/JSON details. The source of truth for numeric checks is `tools/`; warnings and record consistency do not certify a model.

1. Declare the physical task and any explicit precision objective before choosing orbitals. [Create the material layout](docs/MATERIAL-LAYOUT.md). [Prepare DFT](docs/DFT-PREPARATION.md) if needed, or use the authorized SCF and projected-band results. Select from the projected **band path**; no independent mesh or PDOS calculation precedes selection. [Import VASP outputs](docs/VASP-CACHE.md) and draw the official DFT/projected-band figures.
2. Use the decision card to resolve task/basis, both valence lower edges, conduction outer and the positive frozen upper candidate separately. After each draft proposal, run `tools/selection_scope_audit.py` (automatic in `review_workflow.py propose`) and inspect unprotected target valence, actual scalar membership and upper origin before answering conduction questions. These are review facts; no variable changes automatically. Run `tools/review_packet.py` and inspect full-path plots and raw element-by-shell weights. Follow the [first-trial card](docs/FIRST-TRIAL-CARD.md) in order: task anchors and concentrated deep-block roles → basis with channel roles and inclusion/omission risks → target/reference → independent valence outer/frozen lower edges → optional safe prefix exclusion → physically motivated conduction outer → positive frozen candidate → frozen-only counterexample screen. Main chemical candidates are block p/d/s. Included extra channels need independent task-state witnesses; unresolved roles may be exploratory. Global-gap absence does not require a deep-only channel or equal valence window edges. Review upper continuation against all computed states, not only declared reference rows, and check data sufficiency after setting the physical outer.
3. Save an [initial baseline and reviewed real first try](docs/DECISION-STAGES.md) with distinct `selection.png/pdf`, reasons, warnings and input hashes. Before selecting a real first try or retry, run `tools/conduction_review.py questions` on the draft. First revise the scientific choice if the current target scope, outer continuation or frozen candidates demand it. With positive low-conduction target evidence and no candidate-local counterexample, actually propose a higher frozen draft; do not stop at a valence-only frozen without a physical explanation. Fill the answer template for the latest draft, then **re-propose after editing `review.json`**, run fresh questions and `check` on that exact proposal. `check` rejects a stale selection/review pair, and `decision_stages.py select` enforces the same evidence gate. A retry records the preceding calculation and its change. Figures and the per-material page are produced by default; the [cross-material selection gallery](docs/SELECTION-GALLERY.md) is also refreshed for sealed cases. In selection-only evaluations, use the documented `case/initial`, `case/real_first_try`, `case/retry_NNN` layout; `propose` then refreshes the gallery by default. Run the gallery CLI on the explicit result root when refreshing or using another layout, and submit its manifest with the choices. See [independent review](docs/INDEPENDENT-REVIEW.md) and [evaluation/knowledge boundaries](docs/EVALUATION-AND-KNOWLEDGE.md). Blind mode excludes historical answers; fresh context without filesystem isolation is not a strict blind test.
4. [Generate Wannier interface matrices](docs/WANNIER-INTERFACE.md) from SCF charge in the default single NSCF, or from a sealed shared WAVECAR with VASP `ALGO=None` when repeatedly testing the same DFT mesh. For a shared-WAVECAR benchmark, enforce `require_shared_wavecar=true` in the private execution profile and retain the no-fallback contract. The optional Slurm reference uses `sites/slurm-shared-wavecar.example.json`; the template is not a deployment requirement. For a new basis or `exclude_bands`, regenerate matching matrices; for a window-only retry, reuse them. Check the actual interface k mesh, exclude boundary, matrix identity, state counts and computed-band top before Wannier90. Choose the physical outer first: if the projected path or interface band top is insufficient for it, keep the justified window and add the needed non-self-consistent bands rather than shrinking outer to pass a gate. Report `N_outer-num_wann` separately from band-top margin. [Run disentanglement only](docs/WANNIER-EXECUTION.md): explicit `num_iter = 0`, independently controlled `dis_num_iter`, and `write_hr`, `write_rmn`, `write_tb`, `bands_plot` all true. [Compare](docs/WANNIER-COMPARISON.md) at the DFT k points, keeping convergence, products, fixed physical target and fit separate.

After an actual trial, use the short [window retry card](docs/WINDOW-RETRIES.md). Review clean low-conduction target protection when it is absent; when substantial high-conduction protection is already present, test a lower frozen upper edge with basis and outer fixed. Keep result-driven constraint release separate from the projection negative screen. For a test with an explicit scientific-trial budget, an unaccepted fit or unconverged disentanglement is a result to diagnose, not a stopping condition by itself. If data and budget remain, record the failed result and submit the next physically justified trial; stop at the declared acceptance gate, exhausted budget, or a documented data blocker.

The release is an allowlisted tool and skill package. It contains no historical material choices. Its manifest verifies content integrity, not scientific accuracy or runtime isolation.

For existing-DFT tests, use `selection.json#/dft_space_assessment` after fixing the physical outer, then the separate actual-interface assessment. `needs_more_data` routes to the required non-self-consistent data, preserving the physical candidate. Reuse existing sufficient data; a poor fit alone does not establish a need for more bands, and no material's high-band workaround is a general NBANDS default.

English is canonical for execution; Chinese reading translations are separate. See the [documentation policy](docs/DOCUMENTATION.md). With bounded MCP reads, continue at `next_offset` until the required reference is complete.
